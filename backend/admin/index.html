Embed snippet
This is the entire integration a tenant's site needs — one script tag, pasted anywhere in their HTML. The key isn't a true secret (it's sitting right here in this page's source once embedded) — its purpose is per-tenant rate-limit handling and the ability to revoke/rotate one tenant's key without affecting any other tenant. Regenerating immediately invalidates the old key — any site still using it will get blocked until it's updated with the new snippet.
Branding / theme
Overrides the widget's default colors. Covers borders, message backgrounds, and soft text — a few elements (the launcher button, some shadows) aren't wired to this yet.
Suggested starter questions
Booking form fields
Field name is the internal key. Description is what the bot asks for AND what the extraction step uses to understand what to pull from the customer's reply.
Serviced countries
Consultancy-vertical tenants only. This is the HARD boundary the bot enforces — if a destination country isn't listed here, the bot refuses to answer visa/process questions about it rather than guessing from general knowledge. Leave empty to disable this check entirely for this tenant.
LLM provider / models
Models are tried on OpenRouter in the order listed, left to right, on every chat turn. Once you set any models here, the platform's automatic free-model safety net is skipped entirely for this tenant — this list is exactly what gets requested, nothing added silently. Leave blank to keep using the platform default chain (Gemini 2.5 Flash + a couple of built-in free fallbacks).
Offices
Consultancy-vertical tenants only. "Serves destinations" is a comma-separated list of countries this office handles visas/applications for — the bot uses it to point users to the right office instead of listing all of them.
Data residency (advanced)
Optional dedicated infrastructure for this tenant. Leave any field blank to keep that piece on the shared platform default — this isn't all-or-nothing, e.g. a tenant can have a dedicated database while still sharing the default vector search. Config (FAQs, prompts, branding) always stays on the shared platform regardless — only this tenant's own end-user data (leads, chat transcripts, and/or document vectors) moves. Apply db/schema-tenant-dedicated.sql to a dedicated database before pointing this at it.
Advanced: raw JSON (everything else — persona, integrations, allowed origins, vertical…)
